# 逐行事件 caption

事件仍保存一个 `caption` 字符串，以换行分隔清楚、可独立理解的观察。保持 P → PH → E 层级；没有新增分维度字段、句子节点或 source 记录。

## 写作约定

- 每行一句完整的话，围绕一个主要观察保留必要细节。对象可以确定时明确主语，不能为了补齐主语猜测身份。
- 有证据的动作或变化按观察顺序排列；同时或静态信息不强行写成“先……再……”。
- 保留可见文字、重复实例、状态变化、否定和不确定性，不从缺帧、遮挡或相似外观推断未见行为。
- 行数由内容决定；只有一条事实时允许一行。不使用编号、项目符号、维度标题或 JSON 数组。
- 阶段结束时把所有成员整理为同一个 E 的多行 caption。去除同一次观察的重复措辞，保留多次发生的实例；PH/P 只概括主题与过程。

以下是格式示意，不是视频实跑结果，也不放入通用模型提示词：

```text
P：在商店中浏览电子产品。
└─ PH：浏览游戏外设区域。
   └─ E：
      镜头向右扫过游戏手柄展示架。
      随后镜头向左转动，出现 PS4 展示台。
      PS4 展示台上方有一块蓝色标牌。
```

序列化时仍是一个合法 JSON 字符串，例如：

```json
{"caption":"第一条有证据的观察。\n第二条有证据的观察。"}
```

模型应输出 JSON 的 `\n` 转义，解析后存储真实换行。展示层保留换行，不按标点重写旧 caption，也不伪造逐句时间或逐句帧对应。

## 覆盖范围与验证边界

独立前端的 `CAPTION_SYSTEM` 与阶段结束的 `COLLAPSER` 共享 `caption_style.py` 的写作规则；归组提示词明确每行不是新 E/PH。研究工作目录中用于 E 新建/续写的提示词也采用相同格式，但该历史适配入口未包含在本精简仓库中。

当前 v10 重放入口仍接收外部写好的 E，因此开放阶段及待组织区的旧单段 caption 不会被自动改写。存储保持兼容，不以句号或行数验证语义。提示词改动尚未经过真实模型新生成或 QA 评测，不能据此声称检索效果改善。
